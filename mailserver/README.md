# Свой почтовый сервер с регистрацией ящиков

Полный комплект: приём/отправка почты на своём домене, веб-почта (Roundcube)
и страница, где люди сами регистрируют себе адрес `имя@ваш-домен`.

Внутри — [docker-mailserver](https://docker-mailserver.github.io/docker-mailserver/latest/)
(Postfix + Dovecot + Rspamd + Fail2ban), всё запускается одной командой через Docker.

## Что понадобится

1. **Домен** — купите у любого регистратора (Namecheap, Cloudflare, reg.ru…).
2. **VPS с белым IP** — от 1 ГБ ОЗУ достаточно. **Важно:** у многих хостеров
   исходящий порт 25 закрыт по умолчанию (Hetzner, DigitalOcean, AWS...).
   Перед покупкой/настройкой напишите в поддержку хостера и попросите открыть
   порт 25 — без него сервер не сможет отправлять почту.
3. **rDNS (PTR-запись)** — в панели хостера пропишите обратную DNS-запись
   для IP сервера: `mail.ваш-домен`. Без неё Gmail и другие будут отклонять письма.

## Установка

```bash
git clone https://github.com/skarausa212-arch43/bestwayplus-.git
cd bestwayplus-/mailserver
cp .env.example .env
nano .env              # впишите свой домен
```

Сначала добавьте в DNS **A-запись** (см. таблицу ниже, первая строка), подождите
5–10 минут, затем:

```bash
bash setup.sh
```

Скрипт установит Docker, получит TLS-сертификат, запустит сервер, создаст
служебный ящик `postmaster@` и сгенерирует DKIM-ключ.

## Записи DNS (добавить у регистратора)

Замените `example.com` на свой домен, `1.2.3.4` — на IP сервера.

| Тип | Имя | Значение | Зачем |
|-----|-----|----------|-------|
| A | `mail` | `1.2.3.4` | адрес почтового сервера |
| MX | `@` | `mail.example.com` (приоритет 10) | куда доставлять почту для домена |
| TXT | `@` | `v=spf1 mx -all` | SPF: разрешает отправку только с вашего сервера |
| TXT | `mail._domainkey` | *(выведет setup.sh)* | DKIM: криптоподпись писем |
| TXT | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:postmaster@example.com` | DMARC: политика для подделок |

Плюс **PTR (rDNS)** в панели хостера: `1.2.3.4 → mail.example.com`.

Проверить настройку: [mail-tester.com](https://www.mail-tester.com) — отправьте
туда письмо и добейтесь оценки 10/10. DNS-записи удобно проверять на
[mxtoolbox.com](https://mxtoolbox.com).

## Регистрация ящиков

Страница регистрации крутится на `127.0.0.1:8081`, веб-почта — на `127.0.0.1:8080`.
Наружу их публикует nginx — готовый пример в `nginx.conf.example`
(регистрация на `https://mail.ваш-домен/`, почта на `/webmail/`).

В `.env` есть `INVITE_CODE`:

- **пустой** — регистрация открыта всем. Осторожно: спамеры быстро находят
  открытую регистрацию, и репутация домена умрёт;
- **задан** — ящик создаётся только по коду приглашения. Рекомендуется.

Защита уже встроена: не больше 5 регистраций с одного IP в час,
зарезервированные имена (admin, postmaster...) занять нельзя.

## Мульти-почта: 20 ящиков на одном экране

Сервис `multimail` (порт `127.0.0.1:8082`, через nginx — `https://mail.ваш-домен/multi/`)
позволяет добавить **до 20 ящиков сразу** и работать с ними на одной странице:

- общая лента входящих всех ящиков (каждый ящик помечен своим цветом)
  или просмотр по одному ящику — переключение в сайдбаре;
- счётчики непрочитанных по каждому ящику и общий;
- чтение писем (HTML-письма открываются в изолированном фрейме) и ответ/отправка
  от имени любого добавленного ящика;
- галочка «запомнить в этом браузере» — при следующем заходе все ящики
  подключатся сами (пароли хранятся в localStorage вашего браузера);
- автообновление раз в минуту.

Пароли ящиков живут в серверной сессии (в памяти контейнера) и никуда не
записываются; после перезапуска контейнера ящики переподключатся из браузера,
если стояла галочка «запомнить».

## Настройки для почтовых программ (Outlook, Thunderbird, телефон)

| | Сервер | Порт | Шифрование |
|---|--------|------|-----------|
| Входящая (IMAP) | `mail.ваш-домен` | 993 | SSL/TLS |
| Исходящая (SMTP) | `mail.ваш-домен` | 465 | SSL/TLS |

Логин — полный адрес (`ivan@ваш-домен`), пароль — из регистрации.

## Управление

```bash
docker exec mailserver setup email list            # список ящиков
docker exec mailserver setup email add a@dom pass  # создать ящик вручную
docker exec mailserver setup email del a@dom       # удалить ящик
docker exec mailserver setup email update a@dom p  # сменить пароль
docker logs -f mailserver                          # логи
```

Данные писем лежат в `docker-data/` — включите её в бэкапы.

Продление сертификата: добавьте в cron `certbot renew --deploy-hook "docker restart mailserver"`.
