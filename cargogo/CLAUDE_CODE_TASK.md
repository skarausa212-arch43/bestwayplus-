# ЗАДАНИЕ ДЛЯ CLAUDE CODE — доводка CargoGo MVP

В этом репозитории готовый каркас MVP по ТЗ (CargoGo_MVP_Claude_Code_Spec.md).
Реализовано: обе роли, мастер заказа, машина статусов, чат, заработок, админ-панель,
сквозные уведомления (push + in-app toast + центр уведомлений).

## Шаг 1 — запуск и проверка
1. `npm install`
2. `npm run typecheck` — исправь ВСЕ ошибки TypeScript
3. `npx expo start` — приложение должно запускаться без red screen
4. Прогони демо-сценарий из README (клиент → заказ → водитель → код 4217)

## Шаг 2 — обязательные доработки
1. **AsyncStorage-персистентность**: обернуть zustand-сторы (orders, driver, notifications)
   в persist-middleware, чтобы состояние переживало перезапуск.
2. **Локализации**: создать src/i18n/ru.ts, en.ts (полные копии структуры pl.ts с переводом),
   заглушки uk/be/de. Добавить переключатель языка в профили.
3. **Экран деталей заказа из истории** (сейчас история только списком).
4. **Ожидание (§36 ТЗ)**: таймер бесплатных 10 минут на статусе driver_arrived,
   после — счётчик платного ожидания 2 zł/min, добавление в price.waiting.
5. **Запрос изменения цены (§37)**: водитель отправляет причину+сумму,
   клиент получает уведомление и подтверждает/отклоняет в чате.
6. **Доп. остановки (до 3) в мастере заказа** — поле уже есть в типах (stops).

## Шаг 3 — по желанию (если останется бюджет времени)
- react-native-maps вместо MockMap (интерфейс совместим: markers/route/progress)
- Фото груза через expo-image-picker (mock-кнопки уже стоят)
- Zod-схемы валидации форм (zod и react-hook-form уже в зависимостях)

## Правила
- НЕ менять src/config/app.ts структуру — название бренда меняется только там
- Все новые строки UI — только через t() и файлы локализации
- Уведомления — только через notify() из services/notifications.ts
- Не подключать реальные платежи/SMS (§59 ТЗ)
- После каждого блока: npm run typecheck && перезапуск expo

## Definition of Done
- [ ] typecheck без ошибок
- [ ] Полный сценарий клиента проходит без крешей
- [ ] Полный сценарий водителя проходит (регистрация → одобрение → заказ → код → заработок)
- [ ] Уведомления приходят обеим ролям на каждый статус
- [ ] Нет неработающих кнопок (mock-заглушки показывают Alert)

## Шаг 2.5 — ПЕРЕНОС ЛОГИКИ ИЗ HTML-ПРОТОТИПА (приоритет!)
В файле docs_html_demo.html — рабочий прототип, где логика уже отлажена и утверждена.
Перенеси в React Native 1-в-1:
1. **i18n на 3 языка (pl/ru/en)** — словари I18N из прототипа скопировать в src/i18n/pl.ts, ru.ts, en.ts.
   У каждого пользователя свой язык (поле в профиле + переключатель PL/RU/EN).
   Уведомления рендерятся на языке роли-ПОЛУЧАТЕЛЯ (см. notify/renderNotifTitle в прототипе).
2. **Автоперевод чата**: быстрые фразы = ключи словаря (мгновенно);
   свободный текст — серверный вызов перевода (Claude API или DeepL), структура
   сообщения {text, lang, tr:{pl,ru,en}, pending} как в прототипе, пометка "🌐 переведено".
3. **Платное ожидание (§36)**: на статусе driver_arrived таймер 10 бесплатных минут,
   далее 2 zł/мин, баннер у обеих ролей, уведомление при переходе на платное,
   доплата в order.price.waiting и в total (функции startWait/stopWait из прототипа).
   В prod тик = 60000 мс (в прототипе 3000 для демо).
4. **Изменение цены водителем (§37)**: sendPriceReq/answerPriceReq из прототипа —
   форма у водителя (сумма+причина), карточка принять/отклонить у клиента, уведомления обеим сторонам.

## Шаг 4 — сборка iOS
1. Локальная проверка: npx expo start → Expo Go на iPhone (QR-код).
2. eas login && eas build:configure
3. eas build --platform ios --profile preview  (сборка в облаке EAS, Mac не нужен)
4. eas submit --platform ios  → TestFlight (нужен Apple Developer аккаунт владельца).
Не хардкодить ключи; секреты через eas secret.
