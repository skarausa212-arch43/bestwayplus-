# Запуск на macOS

## Запуск: AndroidEmulator.app

```bash
tar -xzf android-emulator-macos.tar.gz
cd android-emulator-macos
xattr -dr com.apple.quarantine AndroidEmulator.app     # см. ниже
open AndroidEmulator.app
```

Дальше — двойной клик по `AndroidEmulator.app` в Finder, как по любому
приложению. Оно само поднимает панель и открывает окно без адресной строки и
вкладок; закрыли окно — остановились и панель, и все запущенные устройства.

**Первый запуск** займёт несколько минут: в архиве нет `node_modules`, поэтому
приложение само поставит зависимости и скачает Chromium (~150 МБ). Оно делает
это в открытом окне Терминала — специально видимом, чтобы приложение не
выглядело зависшим. Дальнейшие запуски мгновенные.

Требуется только Node.js 20+. Приложение ищет его в Homebrew (`/opt/homebrew`,
`/usr/local`), у официального установщика, а также в nvm, volta и asdf: у
приложения, запущенного двойным кликом, PATH урезан до системного, поэтому
искать приходится вручную. Если Node не найден — увидите диалог с объяснением.

Внутри бандла — универсальный бинарник (arm64 + x86_64), так что одна и та же
папка работает и на Apple Silicon, и на Intel. Go **не нужен**: собранные
бинарники прокси для обеих архитектур лежат в `tools/tlsproxy/bin/`.

## Gatekeeper

Приложение не подписано. Если архив пришёл через браузер, AirDrop или
мессенджер, macOS ставит на файлы карантин, и на **неподписанный `.app`**
реакция жёстче, чем на обычный бинарник: Finder скажет, что приложение
«повреждено и не может быть открыто». Это не повреждение — это карантин.

Снимается одной командой в Терминале, из папки с приложением:

```bash
xattr -dr com.apple.quarantine AndroidEmulator.app
```

Если распаковывать архив командой `tar` в Терминале, карантин обычно не
ставится вовсе, а вот двойной клик по архиву в Finder его проставляет.

Не хотите запускать чужой неподписанный бинарник — соберите свой, исходники в
архиве (нужен Go 1.25+):

```bash
cd tools/launcher
GOOS=darwin GOARCH=arm64 go build -o ../../AndroidEmulator.app/Contents/MacOS/AndroidEmulator .
```

Хеши того, что собрано в архиве, лежат в `VERSION`.

## Из терминала, без приложения

```bash
npm install
npx playwright install chromium
node bin/cli.js gui        # панель на http://127.0.0.1:7333
node bin/cli.js verify pixel-8-pro
```

## Что работает так же, как на Linux

Всё, кроме одного пункта ниже. TLS-слой, HTTP/2, порядок заголовков,
JS-инъекция, CDP-эмуляция, cookies, вышестоящий прокси — платформо-независимы.
`node bin/cli.js verify <device>` покажет фактическое состояние.

## Что на macOS не работает: ограничение набора шрифтов

Это единственное содержательное отличие, и оно принципиальное.

Слой шрифтов держится на fontconfig, а **Chromium читает fontconfig только на
Linux**. На macOS Skia работает через CoreText, и ни одного способа скрыть
системные шрифты от одного процесса CoreText не предоставляет. Поэтому:

- `--fonts` на macOS **принимается, но не действует**. Код говорит об этом
  прямо — в консоль уходит предупреждение `font restriction inactive: ...`, а
  `verify` понижает соответствующие проверки до предупреждений вместо ошибок.
  Молчаливое «сработало» было бы хуже всего: вы бы считали проверку закрытой.
- JS-слой продолжает работать: определение шрифтов через **canvas-метрики**
  закрыто полностью, потому что это уровень скрипта.
- Открытым остаётся определение через **DOM-раскладку** (отрисовать строку в
  `"Target", monospace` и сравнить `offsetWidth`). Оно идёт внутри движка
  вёрстки, ниже всего, до чего дотягивается скрипт. Сайт, который так проверяет,
  увидит шрифты вашего Mac — Helvetica Neue, SF Pro и прочие, которых на Android
  нет.

Насколько это важно, зависит от задачи. Для отладки вёрстки, проверки
UA/client hints, TLS-отпечатка и сетевого поведения — не важно вовсе. Если вам
нужен именно полный набор шрифтов Android, единственный честный вариант —
Linux. Достаточно контейнера:

```bash
docker run --rm -it -v "$PWD":/app -w /app node:22-bookworm bash
apt-get update && apt-get install -y fontconfig
npm install && npx playwright install --with-deps chromium
node tools/fetch-fonts.mjs ./android-fonts
node bin/cli.js verify pixel-8-pro --fonts ./android-fonts
```

Там та же команда даёт 70/71 с полностью закрытым DOM-детектом шрифтов.

## Прочие мелочи

**Песочница Chromium.** На macOS вы работаете не от root, поэтому `--no-sandbox`
не добавляется — песочница остаётся включённой, как и должна.

**DNS.** Бинарники собраны с `CGO_ENABLED=0`, то есть используют
резолвер на чистом Go, а не системный. Это намеренно: имена должны
резолвиться по маршруту прокси, а не по настройкам машины. Практическое
следствие — записи из `/etc/hosts` учитываются, а специфичные для macOS
источники конфигурации DNS (профили VPN, Bonjour) — нет.

**Первый запуск.** Скачивается около 150 МБ Chromium. Если Playwright той же
версии уже стоит, шаг отработает мгновенно.

**Где живёт состояние.** `profiles-data/<device>-<seedId>/` внутри папки
приложения: cookies, localStorage и локальный CA. Приложение запускает сервер с
рабочим каталогом этой папки, поэтому состояние не зависит от того, откуда
приложение открыли.

**Версия Playwright** зафиксирована точно (`1.56.1`), чтобы версия библиотеки и
сборка браузера всегда совпадали. Это осознанный выбор в пользу
воспроизводимости; при обновлении меняйте оба вместе.
